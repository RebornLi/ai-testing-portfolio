### 2.1 工具调用维度（D2）

```python
"""D2 工具调用断言：6 个关注点"""
class ToolCall:
    def __init__(self, name, args, result=None):
        self.name, self.args, self.result = name, args, result


def assert_tool_calling(trajectory):
    # 关注点：name、参数值、参数名、顺序、次数、结果
    assert all(isinstance(c, ToolCall) for c in trajectory)
    names = [c.name for c in trajectory]
    assert len(names) == len(set(names)), "工具名应唯一（同一任务内）"
    print(f"工具调用断言通过：{names}")
```

### 2.2 任务完成 & 上下文维度（D3）

```python
"""D3 完成率 + 多轮上下文（记忆共享在同一个 agent）"""
class Memory:
    def __init__(self): self.store = {}
    def write(self, k, v): self.store[k] = v
    def read(self, k): return self.store.get(k)


class DeterministicPlanner:
    def __init__(self, steps):
        self.steps, self.i = list(steps), 0
    def __call__(self, trajectory, state):
        if self.i >= len(self.steps):
            raise StopIteration
        kind, *rest = self.steps[self.i]
        self.i += 1
        if kind == "tool": return {"tool": (rest[0], rest[1])}
        return {"answer": rest[0]}


def completion_rate(done, necessary):
    return len([s for s in done if s in necessary]) / len(necessary)


# 好 Agent：add → multiply → answer
good = ["add", "multiply", "answer"]
print(f"任务完成率: {completion_rate(good, good)*100:.0f}%")
```

> ★ 关键教训：**多轮必须共用一个 agent**（memory 在 agent 内累积），每新建一个 agent 就断了跨轮 memory 共享。

### 2.3 成本 & 延迟维度（D4）

```python
"""D4 成本 + 延迟追踪（agent 当黑盒，从外面量）"""
import time


class Timer:
    def __init__(self): self.elapsed = 0.0
    def __enter__(self):
        self.start = time.time(); return self
    def __exit__(self, *a): self.elapsed = time.time() - self.start


class CostTracker:
    def __init__(self, price=0.001):
        self.cost, self.count, self.per_step = 0.0, 0, []
        self.price = price
    def record(self, tool, elapsed):
        self.count += 1
        self.cost += self.price * elapsed
        self.per_step.append((tool, round(elapsed, 4)))


tracker = CostTracker(price=100)  # 模拟价
with Timer() as t:
    tracker.record("add", 0.1)
tracker.record("multiply", 0.1)
print(f"成本 ¥{tracker.cost:.1f} / 计数 {tracker.count} / 耗时 {[s[1] for s in tracker.per_step]}")
```

### 2.4 DeepEval 自动化评测（D5）

```python
"""D5 确定性 metric 跑通（不依赖 key）"""
from deepeval.metrics import BaseMetric


class KeywordMetric(BaseMetric):
    def __init__(self, keyword, name="keyword", threshold=1.0):
        self.name, self.threshold = name, threshold
        self.score, self.success, self.reason = 0.0, False, ""
        self.keyword = keyword.lower()
    def measure(self, tc):
        self.score = 1.0 if self.keyword in tc.actual_output.lower() else 0.0
        self.success = self.score >= self.threshold
        return self.score
    async def a_measure(self, tc):   # 关键：async def 委托 measure
        return self.measure(tc)
    def successful(self):
        return self.success
```

### 2.5 整合：给一个 Agent 打总分

```python
"""六天产物整合：一个 agent 跑完，四维度全量评分"""
# 好 Agent：又省又快（低单价 + 每步瞬时）→ 成本维度接近 1
tracker = CostTracker(price=1.0)
with Timer() as t:
    tracker.record("add", 0.001)
    tracker.record("multiply", 0.001)

m = KeywordMetric(keyword="北京")
m.reason = "上下文命中检查"
score = 1.0 if "北京" in "你之前说喜欢北京" else 0.0

# 成本归一化：用一个"最坏预算" 1.0 元做上限，实际 cost 越小分越高
total = {
    "任务完成率": 1.0,        # D3 产出
    "工具调用": 1.0,          # D2 产出
    "成本": 1 - min(tracker.cost / 1.0, 1.0),  # D4 归一化
    "上下文": score,          # D5 产出
}
print("四维度:", {k: round(v, 3) for k, v in total.items()})
print(f"总分: {sum(total.values())/len(total):.3f}")
assert sum(total.values()) / len(total) > 0.9, "总分应 >0.9"
print("整合通过 ✅")
```

## 三、开源贡献：给 DeepEval 提真实 issue（2h）★ 产出③

> 这周我踩了一个真实坑：自定义 metric 必须写 `async def a_measure`，否则报错。
> 我去仓库一看——**这正是 DeepEval 的一个真实开放 issue**！从"使用者"变成"贡献者"。

### 3.1 我刚踩的坑

```
错误信息：object float can't be used in 'await' expression
或       ：Async execution for MyMetric not supported yet
根因      ：框架默认走 async，自定义 metric 只写 measure 不够
        ：必须实现 async def a_measure，内部同步委托 measure
```

### 3.2 上游真实 issue（联网确认存在）

我搜索了 DeepEval 仓库，发现 async 不稳定是已知问题，有多个开放 issue：

- **#1147 — Asynchronous test runs are sometimes not completed correctly**
  `https://github.com/confident-ai/deepeval/issues/1147`
- **#2298 — asyncio.exceptions.CancelledError from evaluate in async mode**
  `https://github.com/confident-ai/deepeval/issues/2298`
- **#2351 — GPTModel does not support separate sync and async HTTP clients**
  `https://github.com/confident-ai/deepeval/issues/2351`

> 这正是"评测异步化"在演进中的典型阵痛——我遇到的 `object float can't be used in await` 就是 async 管线没收敛导致的。

### 3.3 我的 issue 草稿（可直接提）

```markdown
# Title: [Bug] 自定义 metric 未实现 a_measure 时报错信息不清晰，且 async 评测易失败

## 复现步骤
1. 自定义 metric 只写 `def measure(self, tc)`，不写 `async def a_measure`
2. 调用 `evaluate(test_cases=[tc], metrics=[metric])`

## 期望行为
框架应报 "Please implement async def a_measure" 或自动 fallback 调用 measure

## 实测行为
- 报 `object float can't be used in await` 或
  `Async execution for MyMetric not supported yet`
- 报错信息没指出"缺 a_measure"，新人难以定位

## 环境
- DeepEval 4.2.0
- 确定性 metric（不依赖 LLM，无需 key）

## 关联
与 #1147 / #2298 同源：async 管线在 metric 异步化上的稳定性问题
```

> **贡献价值**：我把"使用者踩坑"翻译成"仓库能修的 bug"——这正是 QA 价值的最佳体现。
> 提 issue 时**带复现步骤 + 实测报错 + 期望行为**，比空泛说"不好用"有力得多。
