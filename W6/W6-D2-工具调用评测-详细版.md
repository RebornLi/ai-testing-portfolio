## 一、为什么工具调用维度最细（1.5h）★ 今日重点

> 一句话：**答案对错一眼能看，但工具用没用对，得一步步扒。**

Agent 做事靠工具（搜索、计算、查库）。"做对了"要拆成很多个小正确：

- 工具名对吗？（该算账不该查天气）
- 参数对吗？（该加不该乘）
- 参数名对吗？（`city` 还是 `cities`）
- 顺序对吗？（先加再乘）
- 次数对吗？（该调 2 次还是多调了）
- 结果对吗？（工具返回算得对不对）

> 答案对了，不代表过程对了。工具调用维度就是"拿放大镜看过程"。

---

## 二、工具调用 5 个断言关注点（★ 核心）

给一个工具调用 `ToolCall(name, args, result)`，可以断言：

| # | 关注点 | 断言什么 | 反例 |
|---|---|---|---|
| 1 | **工具名** | `call.name` 是否期望的工具 | 该 `add` 去 `weather` |
| 2 | **参数值** | `call.args` 与预期完全一致 | 该 `{a:3,b:4}` 写成 `{a:3}` |
| 3 | **参数名** | 用的 key 对不对 | `city` 写成 `cities` |
| 4 | **调用顺序** | 各步 name 的顺序 | 该 `add→multiply` 变成 `multiply→add` |
| 5 | **调用次数** | 工具被调了几次 | 该调 2 次却调了 3 次 |
| 6 | **结果** | `call.result` 是否工具正确输出 | 3+4=7，不是 6 |

## 三、用 W6-D1 的 Agent（确定性，已验证）★ 产出①

> 复用车用 D1 的结构：`ReActAgent` + 固定 `DeterministicPlanner` + 工具集 `tools.py`。
> 任务：先 `add(3,4)` 再 `multiply(7,2)`，答案 14。

先建工具集（不依赖真实服务，确定性）：

```python
"""工具集：确定性，可复现，不依赖外部服务"""
TOOLS = {"add", "lookup", "multiply", "weather"}


def invoke_tool(name, args):
    if name == "add":
        return args["a"] + args["b"]
    if name == "multiply":
        return args["a"] * args["b"]
    if name == "lookup":
        db = {"beijing": "晴天", "atlantis": "未知"}
        return db.get(args.get("city", "未知城市"))
    if name == "weather":
        return "晴天 25°C"
    raise ValueError(f"未知工具：{name}")
```

agent 核心（D1 同款，带 `replay()` 支持轨迹重放）：

```python
"""ReAct Agent：按固定动作序列执行，记录轨迹，可重放"""
from tools import TOOLS, invoke_tool


class ToolCall:
    def __init__(self, name, args, result=None):
        self.name, self.args, self.result = name, args, result


class ReActAgent:
    def __init__(self, planner, max_iterations=10):
        self.planner, self.max_iterations = planner, max_iterations

    def run(self, initial_prompt):
        trajectory, state = [], ""
        for _ in range(self.max_iterations):
            decision = self.planner(trajectory, state)
            if "answer" in decision:
                return {"answer": decision["answer"], "trajectory": trajectory,
                        "reason": "stopped"}
            name, args = decision["tool"]
            result = invoke_tool(name, args)
            trajectory.append(ToolCall(name, args, result))
            state += f"\n[{name} {args} -> {result}]"
        return {"answer": None, "trajectory": trajectory, "reason": "max_iterations"}

    def replay(self, trajectory):
        """重放轨迹，返回每步结果 [result, ...]"""
        return [invoke_tool(c.name, c.args) for c in trajectory]


class DeterministicPlanner:
    def __init__(self, steps):
        self.steps, self.i = list(steps), 0

    def __call__(self, history, state):
        if self.i >= len(self.steps):
            raise StopIteration
        kind, *rest = self.steps[self.i]
        self.i += 1
        if kind == "tool":
            return {"tool": (rest[0], rest[1])}
        return {"answer": rest[0]}
```

跑一个任务，拿到轨迹：

```python
"""先加后乘，答案 14"""
plan = DeterministicPlanner([
    ("tool", "add", {"a": 3, "b": 4}),
    ("tool", "multiply", {"a": 7, "b": 2}),
    ("answer", "结果是14"),
])
agent = ReActAgent(plan)
res = agent.run("完成任务")
traj = res["trajectory"]

for c in traj:
    print(f"{c.name} args={c.args} result={c.result}")
print("轨迹可重放:", agent.replay(traj))
```

**期望**：`add  {a:3,b:4}  result=7`；`multiply  {a:7,b:2}  result=14`；重放结果 `[7, 14]`。

## 四、写工具调用断言（先写失败测试）★ 产出

> TDD 铁律：**先写会失败的断言 → 确认它失败（因为 Agent 真错了）→ 修正 agent → 变绿。**
> 下面故意让规划器犯错，验证每条断言都能抓住。

### 4.1 好 Agent：所有断言应通过

```python
"""好 Agent：工具名、参数、顺序、次数、结果全对。

★ 注意：DeterministicPlanner 是【有状态】的，run 一次就耗尽。
  每次都要【重新构建】新 agent，否则第二次 run 会因规划器 i 已到尽头而
  StopIteration。这是本笔记反复踩过的坑：复用旧 agent。
"""
good = ReActAgent(DeterministicPlanner([
    ("tool", "add", {"a": 3, "b": 4}),
    ("tool", "multiply", {"a": 7, "b": 2}),
    ("answer", "结果是14"),
]))
chain = good.run("x")["trajectory"]   # trajectory 只含工具调用（ToolCall），答案不在其中

# ① 工具名（轨迹里只有工具调用，"answer" 是终态决策，不进轨迹）
assert [c.name for c in chain] == ["add", "multiply"]
# ② 参数值
assert chain[0].args == {"a": 3, "b": 4}
assert chain[1].args == {"a": 7, "b": 2}
# ③ 结果
assert [c.result for c in chain] == [7, 14]
# ④ 次数
assert sum(1 for c in chain if c.name == "add") == 1
# ⑤ 重放结果
assert good.replay(chain) == [7, 14]
# ⑥ 最终答案（重新建一个 agent，避免复用旧的导致 StopIteration）
answer = ReActAgent(DeterministicPlanner([
    ("tool", "add", {"a": 3, "b": 4}),
    ("tool", "multiply", {"a": 7, "b": 2}),
    ("answer", "结果是14"),
])).run("x")["answer"]
assert answer == "结果是14"
print("好 Agent 全部断言通过 ✅")
```

### 4.2 坏 Agent：每条断言都要扣分

设计三种典型错误，验证断言能抓出来：

```python
"""坏 Agent：没调 add + 参数名写错 + 结果不对"""
bad = ReActAgent(DeterministicPlanner([
    ("tool", "weather", {"city": "beijing"}),        # 错1：该 add 却去 weather（add 根本没被调用）
    ("tool", "lookup", {"cities": "beijing"}),        # 错2：参数名 cities 应为 city
    ("answer", "错"),
]))
bchain = bad.run("x")["trajectory"]

# 抓错1：本该调用 add，结果轨迹里根本没有 add
try:
    assert "add" in [c.name for c in bchain]
    print("漏抓：错误1 没被发现 ❌")
except AssertionError:
    print("正确抓住：错误1 未调用 add ✅")

# 抓错2：参数名写错
if any("cities" in c.args for c in bchain):
    print("正确抓住：错误2 参数名写错 ✅")

# 抓错3：坏 Agent 把 add 调成了 0 次（该 1 次），自己单独建一个好 Agent 对比
adds_bad = sum(1 for c in bchain if c.name == "add")
fresh_good = ReActAgent(DeterministicPlanner([
    ("tool", "add", {"a": 3, "b": 4}),
    ("tool", "multiply", {"a": 7, "b": 2}),
    ("answer", "结果是14"),
]))
adds_good = sum(1 for c in fresh_good.run("x")["trajectory"] if c.name == "add")
print(f"正确抓住：错误3 调用次数，坏Agent={adds_bad}次  vs  好Agent={adds_good}次 ✅")
```

## 五、概念笔记② 落盘（1.5h）★ 产出

> 一句话记忆点：

1. **工具调用维度 = 拿放大镜看过程**：答案对了不算对，过程每一步都得对。
2. **6 个断言关注点**：name、参数值、参数名、顺序、次数、结果。
3. **TDD**：先写会失败的断言，确认它抓住错误，再让 agent 变绿。
4. **轨迹是关键证据**：`trajectory` 里有每一步的 name/args/result，断言都靠它。
5. **重放能力**：`replay(trajectory)` 重新执行轨迹 = 验证过程可复现。
6. **结果也要断言**：工具返回的 `result` 算得对不对，别只盯 name。
