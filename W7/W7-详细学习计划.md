# W7 详细学习计划 · 测试框架搭建 + 工程化

> 时间：2026-08-27（周四）起 · 承接 W6「Agent 评测四维度」
> 目标：把 W6 的四维度评测框架**封装成可复用、进 CI、能 Docker 一键跑通**的流水线
> 产出：`auto-eval/` —— 自动化评测流水线（pytest 全量测试 + 一键评分报告 + Docker + CI）
> 验收：`docker compose run` 一键跑通；GitHub Actions push 即跑全量测试；报告可写 JSON/TXT

---

## 🎯 本周总目标（对标整体规划 W7）

阶段二「AI 核心」第 7 周，从"能跑评测"进阶到"**把评测做成工程**"——这是 AI 测试工程师的核心竞争力：**可复用、可复现、进流水线**。

1. **框架封装**：把零散脚本封装成 `metrics/` + `evaluate.py` + `run_evaluation.py` 的清晰分层。
2. **CI 门禁**：每条 push 自动跑 `pytest tests/ -q`，11 用例全绿才能合并。
3. **Docker 化**：离线 wheels 安装，容器内无网络也能跑通全部评测。
4. **可复现报告**：每次评测写 `reports/evaluation_YYYYmmdd_HHMMSS.json/.txt`。

> 一句话：**W6 造出了评测，W7 把评测变成"能上车、能复现、能对团队"的工程产物。**

## 📅 每日任务（6-8 小时）

### D1（08-27 周四）：评测框架分层设计 + 四维度指标封装 ★
- 学习：为什么要把评测脚本拆成 `system/`（被测）+ `metrics/`（指标）+ `evaluate.py`（引擎）+ `tests/`（用例）
- 实战：重写 `evaluate.py`，跑完四维度打分，修正"answer=None"bug（有状态规划器须新实例）
- 产出：`evaluate.py` 一键评测总分 1.000、4/4 维度通过
- 验收：`python run_evaluation.py` 跑通

### D2（08-28 周五）：pytest 全量用例 + CI 门禁 ★
- 学习：pytest 参数化、`--exitcode` 在 CI 门禁中的作用、为什么"全绿才能合并"
- 实战：写 11 个用例覆盖四维度（工具调用 / 记忆 / 成本 / DeepEval）
- 产出：`tests/` 四维度 11 用例，`pytest tests/ -q` → 11 passed
- 验收：本地 `pytest` 全绿

### D3（08-29 周六）：Docker 镜像 + 离线 wheels 安装 ★
- 学习：Dockerfile 分层缓存、为什么容器内默认无网络、离线 wheels 安装
- 实战：写 `Dockerfile` + `requirements.txt` + `.dockerignore`，`docker build` 离线安装
- 产出：`auto-eval:test` 镜像，`docker run` 跑全量测试
- 验收：`docker build` + `docker run` 离线跑通

### D4（08-30 周日）：Docker Compose 一键跑通 ★
- 学习：docker-compose 的服务、命令、卷（volumes）挂载
- 实战：写 `docker-compose.yml`，把报告落到宿主 `./reports/`
- 产出：`docker compose run --rm auto-eval` 一键跑通
- 验收：`docker compose run` 一键绿

### D5（08-31 周一）：GitHub Actions CI + README 沉淀 ★
- 学习：GitHub Actions 触发条件、CI 门禁四步（拉码→装依赖→测试→门禁）
- 实战：写 `.github/workflows/auto-eval.yml`，README 写清运行/CI 说明
- 产出：`push` 自动跑全量测试；README 可复现
- 验收：CI YAML 校验通过；README 实测命令正确

- 任务：写 W7 一周总结 + 一页纸速记
- 复盘：本周最佳收获 + 下周重点
