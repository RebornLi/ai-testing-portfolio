> 时间：2026-08-28（周五）~ 2026-09-03（周四）
> 目标：掌握 OpenAI 兼容接口的全套测试基本功——参数化批量调用、响应校验、Function Calling、流式、重试限流、性能成本
> 验收：随堂 6 组测试脚本全绿 + 学习日志 + commit（本周以学习笔记 + 随堂练习为主，尚未沉淀为独立工程）

## 🎯 本周总目标

阶段「AI 应用评测」的 **LLM 接口层**。RAG / Agent 都是「调 LLM 构建出来」的，所以先孤立地把「调用 LLM 这件事」测透：怎么调、返回对不对、稳不稳、贵不贵。整条线围绕一个真实本机服务 `vLLM :8000`（模型 `ornith1.5-35b`，一个 thinking 模型）完成。

1. **认识接口**（D1）：OpenAI 兼容协议、核心参数、响应结构
2. **批量调用 + 校验**（D2）：parametrize 一次跑多组，断言每个响应结构都对了
3. **工具调用**（D3）：Function Calling——模型决定调哪个工具，两轮循环
4. **流式测试**（D4）：SSE 分块协议、逐块读取、TTFT、完整性
5. **稳健性**（D5）：重试 + 限流（用 mock 伪造 429 验证）
6. **性能成本**（D6）：TTFT / 时延 / 吞吐 / token / 成本预算
7. **收尾**（D7）：里程碑 + 复盘 + 全部 push

> 关键观念变化：LLM 测试 = 传统接口测试 + **非确定输出** + **花钱/花耗时**。断言要从「精确结果」升级到「schema + 性能区间」。

## 📅 每日任务

### D1（08-28）认识 LLM API ★
- 学习：LLM API = 把模型当「云端函数」（OpenAI 兼容协议）；核心参数 `temperature`/`max_tokens`/`stream`；`/health`、`/v1/models` 自检
- 实战：用 httpx 连本机 vLLM :8000 跑第一次 chat completion
- 产出：核心参数笔记 + 首次完整对话（含 usage / 流式响应）
- 验收：能发一次完整 chat completion + 拿到 usage + 学习日志 + commit

### D2（08-29）参数化批量调用 + 响应校验 ★ 今日重点
- 学习：为什么 LLM 测试要参数化（批量时省钱耗时）；响应结构为什么不能只 `assert 非空`
- 实战：`parametrize` 一次跑 5 组 prompt；校验 `object / choices / finish_reason / usage`
- 产出：`test_llm_batch.py`（5 组 prompt）+ 结构化输出 `response_format=json_object` 实验
- 验收：5 组 prompt 全绿 + 3 个响应校验（含 `finish_reason=="length"` 截断信号）

### D3（08-30）Function Calling 工具调用 ★
- 学习：Agent 本质 = LLM + 工具；`tools` schema 定义；`finish_reason=="tool_calls"` 的两轮循环
- 实战：定义 `add_numbers` 工具，跑「tool_calls → 结果喂回 → 最终答案」；参数化 `tool_calls`（name + arguments）
- 产出：`test_tool_call.py`；异常工具定义 + 终止性（无限 tool loop）测试
- 验收：两轮对话全绿（要工具 → 喂回 → 给答案）

### D4（08-31）流式响应 SSE 测试 ★
- 学习：流式原理（SSE 分块协议）；`chat.completion.chunk` / `delta.content` / `data: [DONE]`
- 实战：httpx SSE 逐块读取 + 拼回完整答案；断言完整性 + TTFT
- 产出：`test_streaming.py`；异常流式（空流 / 超时 / 错误块）
- 验收：逐块读取 + 拼回 == 非流式一次返回 + finish_reason 断言全绿

> ⚠️ 本机思考模型流式时，81 块里有 80 块是 `delta.reasoning`（思考过程）、`delta.content` 为空 → 评测要「剥 reasoning 取纯内容」。

### D5（09-01）重试与限流 ★
- 学习：何时重试（`429 / 503` 是，`400 / 401 / 404` 否）；指数退避 `base × 2^n` 设 cap
- 实战：写 retry 客户端，`monkeypatch` 伪造 429 验证「429 后成功」；客户端侧限流节流
- 产出：`test_retry.py`
- 验收：429 后成功 / 全失败 / 首成功 / 400 立即抛 四类场景全绿

> 铁律：只有「重试可能有用」才重试；400/401/404 立即报错，别浪费。

### D6（09-02）性能与成本度量 ★
- 学习：LLM 三指标 TTFT / 吞吐 / 总时延 + 隐藏维度**成本**（每个 token 都花钱）
- 实战：测 TTFT（首个 reasoning 块）、token 数、总时延；写成本预算断言
- 产出：`test_performance.py`；预算测试 + 慢调用告警
- 验收：TTFT≈0.06-0.10s、`total_tokens`≈132、成本预算断言全绿

### D7（09-03）里程碑 + 复盘
- 任务：写 `milestones/W2-LLM-API-测试.md`；检查分支、清理、准备 push
- 产出：里程碑 + 一周 7 个 commit
- 验收：全部 push 到 GitHub（7+ commit）+ 复盘（完成度 / 卡点 / 下周改进）
