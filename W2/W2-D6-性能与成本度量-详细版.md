## 一、为什么 LLM 性能要专门测（1.5h）★ 今日重点

> 传统软件测试性能，看的是接口 QPS、响应时间。LLM 服务还多两个隐形成本：**钱** 和 **延迟体验**。

### 3 个核心指标
| 指标 | 英文 | 含义 | 为什么重要 |
|---|---|---|---|
| **首 token 时延** | TTFT | 从发请求到第一个字出来 | 决定"感觉快不快" |
| **吞吐** | Throughput | 每秒生成多少 token | 决定服务容量 |
| **总时延** | Latency | 一次完整调用耗时 | 决定用户体验 |

> 还有一个隐藏维度：**成本**。每个 token 都花钱，调用越多越贵。评测时如果忘了计量，上线后账单会吓人。

### 1.1 LLM 性能测试 vs 传统测试
| 对比 | 传统接口 | LLM 接口 |
|---|---|---|
| 输出 | 确定 | 非确定（同输入可能不同） |
| 性能关注 | 时延、QPS | 时延、吞吐、**token 成本** |
| 断言 | 精确结果 | schema + **性能区间** |

> 性能断言是**区间/上限**（"小于 5 秒"），不是精确值——因为机器负载会变。

```
流式 trial0: TTFT=0.100s  reasoning块=120
流式 trial1: TTFT=0.061s  reasoning块=120
```

> ⚠️ 重要发现：本机模型是 **thinking 模型**，流式时 `delta.content` 为空，`delta.reasoning` 有内容。所以"首 token 时延"取的是**第一个 reasoning 块**。这是真实环境特征，测试要按此断言。

> 输入约 12 token + 输出打满到 `max_tokens=120`。`total_tokens` = 输入 + 输出。

```python
"""W2-D6 产出①：LLM 性能 + 成本度量（非流式 + 流式）"""
import os, time
import pytest
import requests

BASE_URL = "http://127.0.0.1:8000"
API_KEY = os.environ.get("LLM_API_KEY", "")
MODEL = "ornith1.5-35b"


def nonstream_chat(prompt, max_tokens=120, temperature=0.0):
    """非流式调用一次，返回 (耗时秒数, 响应字典)。"""
    payload = {
        "model": MODEL,
        "messages": [{"role": "user", "content": prompt}],
        "max_tokens": max_tokens,
        "temperature": temperature,
    }
    headers = {"Authorization": f"Bearer {API_KEY}"} if API_KEY else {}
    t0 = time.perf_counter()
    r = requests.post(f"{BASE_URL}/v1/chat/completions",
                      json=payload, headers=headers, timeout=120)
    r.raise_for_status()
    elapsed = time.perf_counter() - t0
    return elapsed, r.json()


def stream_chat_times(prompt, max_tokens=120):
    """流式调用，返回 (TTFT, 总块数, 总耗时)。

    本机这个模型流式时思考内容在 delta.reasoning 里，
    所以首 token 时延取"第一个非空 delta 块"。
    """
    payload = {
        "model": MODEL,
        "messages": [{"role": "user", "content": prompt}],
        "max_tokens": max_tokens,
        "stream": True,
    }
    headers = {"Authorization": f"Bearer {API_KEY}"} if API_KEY else {}
    t0 = time.perf_counter()
    ttft = None
    blocks = 0
    with requests.post(f"{BASE_URL}/v1/chat/completions",
                       json=payload, headers=headers, stream=True, timeout=120) as resp:
        resp.raise_for_status()
        for line in resp.iter_lines():
            if not line or not line.startswith(b"data:"):
                continue
            raw = line[6:].strip()
            if raw == b"[DONE]":
                break
            try:
                chunk = json.loads(raw)
            except json.JSONDecodeError:
                continue
            delta = chunk["choices"][0].get("delta", {})
            if delta.get("reasoning") or delta.get("content"):
                blocks += 1
                if ttft is None:
                    ttft = time.perf_counter() - t0
    return ttft, blocks, time.perf_counter() - t0


@pytest.fixture(scope="module")
def service_available():
    """服务没起就跳过（不报失败）。"""
    try:
        r = requests.get(f"{BASE_URL}/health", timeout=3)
        if r.status_code == 200:
            return
    except requests.exceptions.RequestException:
        pass
    pytest.skip("vLLM 服务未启动，跳过性能测试")


# —— 非流式性能断言 ——

def test_latency_is_positive(service_available):
    """① 一次调用耗时是正数（可计量）。"""
    elapsed, _ = nonstream_chat("用一句话说说今天", max_tokens=40)
    assert elapsed > 0


def test_latency_within_sla(service_available):
    """② 非流式调用时延 < SLA 上限（本机实测 0.1-0.3s，设 5s 宽松上限）。"""
    for _ in range(2):
        elapsed, _ = nonstream_chat("介绍一下人工智能", max_tokens=60)
        assert elapsed < 5.0        # SLA：单请求不超过 5 秒


def test_total_tokens_positive(service_available):
    """③ 每次调用 total_tokens > 0（成本可计量）。"""
    _, resp = nonstream_chat("介绍一下人工智能", max_tokens=60)
    assert resp["usage"]["total_tokens"] > 0


def test_throughput_estimate(service_available):
    """④ 吞吐估算 = 输出 token / 耗时（应 > 0 tok/s）。"""
    elapsed, resp = nonstream_chat("介绍一下人工智能", max_tokens=60)
    tok = resp["usage"]["total_tokens"]
    throughput = tok / elapsed if elapsed > 0 else 0
    assert throughput > 0


# —— 流式性能断言 ——

def test_ttft_is_measurable(service_available):
    """⑤ 流式首 token 时延（TTFT）能被测到且 > 0。"""
    ttft, blocks, _ = stream_chat_times("介绍一下人工智能", max_tokens=60)
    if ttft is None:
        pytest.skip("本机未检测到首 token 块（模型可能仅输出思考）")
    assert ttft > 0


def test_stream_blocks_complete(service_available):
    """⑥ 流式至少返回若干块（不是空流）。"""
    _, blocks, total = stream_chat_times("介绍一下人工智能", max_tokens=60)
    assert blocks > 0
    assert total > 0
```

## 四、成本估算（1.5h）★ 产出②

> 成本 = 输入 token + 输出 token × 各自单价。LLM 调用越多，成本越高。

### 4.1 成本计算函数
```python
"""LLM 成本估算工具"""


def estimate_cost(prompt_tokens, completion_tokens,
                  input_price_per_m=0.0, output_price_per_m=0.0):
    """计算一次调用成本（美元）。

    单价按"每百万 token"给。
    """
    input_cost = prompt_tokens * input_price_per_m / 1_000_000
    output_cost = completion_tokens * output_price_per_m / 1_000_000
    return input_cost + output_cost


def batch_cost_estimate(total_prompts, avg_completion_tokens,
                        input_price_per_m=0.0, output_price_per_m=0.0):
    """估算一批调用的总成本。"""
    prompt_tokens = total_prompts * 20   # 假设平均每 prompt 20 token
    completion_tokens = total_prompts * avg_completion_tokens
    return estimate_cost(prompt_tokens, completion_tokens,
                         input_price_per_m, output_price_per_m)
```

### 4.2 成本断言
```python
def test_single_call_cost_is_small():
    """⑦ 单次调用成本应是个很小的正数（< 0.01 美元）。"""
    cost = estimate_cost(prompt_tokens=12, completion_tokens=60,
                         input_price_per_m=0.3, output_price_per_m=1.0)
    assert 0 < cost < 0.01


def test_batch_cost_scales_with_prompts():
    """⑧ 调用越多成本越高（线性增长）。"""
    cost1 = batch_cost_estimate(1, 60)
    cost5 = batch_cost_estimate(5, 60)
    assert cost5 == cost1 * 5
```

> 这是成本意识的落地：**评测脚本里记录 token，再换算成钱**。做 LLM 评测时，成本是硬指标。

## 五、预算 + 慢调用告警（1.5h）

> 给一次调用设"成本/时间预算"，超了就 fail——防止跑批时账单失控。

```python
def call_within_budget(prompt, budget_tokens=200, budget_seconds=10):
    """一次调用必须在 token 和时间预算内，否则报错。"""
    elapsed, resp = nonstream_chat(prompt, max_tokens=budget_tokens)
    tok = resp["usage"]["total_tokens"]
    if tok > budget_tokens:
        raise RuntimeError(f"token 超限: {tok} > {budget_tokens}")
    if elapsed > budget_seconds:
        raise RuntimeError(f"时延超限: {elapsed:.2f}s > {budget_seconds}s")
    return tok, elapsed


def test_within_budget_200_tokens():
    """⑨ 单次调用命中预算（token ≤ 200, 时延 ≤ 10s）。"""
    tok, elapsed = call_within_budget("介绍一下人工智能",
                                       budget_tokens=200, budget_seconds=10)
    assert 0 < tok <= 200
    assert elapsed <= 10
```

> 这个 `call_within_budget` 就是生产里"预算门禁"的雏形。

## 🎯 今日关键词

```
TTFT       → 首 token 时延（体验关键）
throughput → 每秒 token 数（容量关键）
latency    → 一次调用总耗时（体验关键）
token      → 计量的基本单位（成本关键）
cost       → token × 单价 = 费用
SLA 上限   → 断言"小于 X"，不是精确值
预算门禁   → 超 token/时间就 fail
```

> 性能测试的精髓：**断言上限，不赌精确**。今天开始，你有了"给 LLM 体检"的能力。
